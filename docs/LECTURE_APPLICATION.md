## 검토 범위와 해석

강의에서 확인한 원칙과 이를 소프트웨어에 옮긴 설계 판단은 구분한다. 아래 자동 검증 구현은 프로젝트에 맞춘 자체 적용이며 강사가 제시한 트리가드 설계가 아니다.

## 실제 검증 결과와 주장 범위

- 현재 보관 원자료: 7개 연도(2019–2025), 14개 지방청과 전국 합계, 총 105행.
- 직접 대조한 숫자: 630개. 연도별 전국 합계 검사: 42건. CSV 다운로드: 7개.
- 오류 주입을 포함한 단위 테스트 7개 통과(잘못된 숫자 테스트 안에 5종 입력 하위 사례).
- 이 결과는 원자료와의 데이터 정합성이다. 예측 정확도 100%, 공식 통계 검증, 기관 도입 성과, 인증 또는 실시간 서비스 가용률이 아니다.
- 배포 결과 보고서는 빌드마다 `dist/data/validation_report.json`으로 새로 생성한다. 성공 여부를 소스 코드에 고정하지 않는다.

## 역할을 분리한 면접 설명

**문제:** 같은 지방청이 여러 시·도를 담당하는 통계를 개별 지역의 값처럼 오해할 수 있고, 코드가 저장소에 반영돼도 운영 배포와 다를 수 있었다.

**최희찬의 역할:** 서비스 요구사항을 제시하고, 기존 지도/통합 관할 동작의 차이를 지적했으며, 원자료 확인 안내와 강의 원칙 적용을 요청했다. 최종 결과 검토와 프로젝트 운영을 담당한다.

**AI 지원 구현:** Codex가 UI·검증기·CI·오류 사례 테스트를 작성하고 배포 및 브라우저 확인을 수행했다. 최희찬이 모든 코드를 직접 작성했다고 표현하지 않는다.

**결과:** 공개 통계 화면의 지역/연도 조회와 출처 안내를 구현했고, 105행·630개 수치 및 42개 합계 검사를 배포 절차에 연결했다. 현재 결과는 데이터 정합성 개선이며 실제 행정 업무 시간 절감이나 운영 효과는 측정하지 않았다.

**질문 대응:**
- “강의의 기술을 그대로 구현했나?” → 일반적인 요구사항 추적·기준 기반 검증·역할 중심 설명 원칙을 적용했다. 레이다/EMC/진동/열설계 시험을 수행한 것은 아니다.
- “반도체·스마트제조와 어떻게 이어지나?” → 원자료 추적, 데이터 계약, 결함 재현, 변경 검증이라는 SW 품질 관리 경험을 설명할 수 있다. 실제 팹 공정 제어·수율 개선 경험과는 구분한다.
- “향후 측정할 성과는?” → 사용자 조회 성공률과 출처 이해도 등을 별도 실험으로 평가할 수 있지만, 현재 달성치로 쓰지 않는다.

## 기관별 공개 수치 복원 확장

강의 2의 77쪽 요구사항 추적과 강의 3의 14쪽 원자료 대조 원칙을 기관 자료에도 적용했다.

- PUB-08: 방위사업청 CSV 3개는 계약방법별 기록 수 및 입찰 참여 기록/업체명 수만 집계한다. 담당자·대표자 이름이나 개별 계약 내용은 화면으로 복사하지 않는다. 기록 수와 고유 계약 수를 구분한다.
- PUB-09: 질병관리청 CSV 4개는 헤더가 없는 파일로 처리한다. 첫 행을 보존하고 전체 셀을 표시하며 검색·20행 페이지 이동을 지원한다. 누락 단위/기간/질병별 열 이름을 추정하지 않는다. 빈 값과 0을 구분하고 열간 합산을 하지 않는다.
- PUB-10: 빌드마다 원본 CSV로부터 기관 자료를 재생성하며 7개 원본 SHA-256과 행 수를 검증 보고서에 남긴다. 원본 셀 전수 대조와 집계 합계 테스트를 기존 CI에 추가했다. 기관 자료의 공식성이나 미확인 메타데이터를 검증했다는 뜻은 아니다.

기관 자료는 지도와 별도 조회 영역이다. 병무청의 연도·시도 선택은 기관별 원자료의 기간·지역을 자동 변경하지 않는다. 통합 군사운용 리스크와 대응 추천은 공개 통계 화면의 구현 범위에 포함하지 않았다.

## 지역 통합 대시보드 확장

Streamlit의 상단 KPI와 지도/분석/상세/가이드 탭 구성을 공개자료 탐색에 적용했다. 지역 선택은 병무청 지방청과 질병청 시도 요약행을 함께 갱신한다. 대구·경북은 각각의 질병청 행과 공동 지방청 하나를 표시한다. 방위사업청은 전국 기록 집계로 표시하며 지역 수치로 간주하지 않는다.

통합 지표는 다음 4개 확인 항목의 통과 개수이며 가중 위험 점수가 아니다: 병무청 값 완비, 질병청 지역행·방위사업청 연결, 보고서의 원본 식별정보 일치, 공통 기준일·단위 확인. 마지막 항목은 현재 미확인으로 고정한다. 연결 실패·출처 불일치·누락에 따라 데이터 보완 안내를 갱신한다. 출처 해시는 수치의 공식성이나 최신성을 보증하지 않는다.

PUB-11: 지역/연도 변경과 공동 관할 연결을 Node 테스트로 확인한다. PUB-12: 자료 누락·출처 불일치·0/null 구분 시 미확인 상태를 검증한다. 기존 Python 9개 검증과 함께 배포 CI에 연결한다.

### 기관 지역 연결 정정

국내조달의 대표업체주소 열을 추가 확인하여 업체 소재지별 기록 집계를 연결했다. 위의 모든 방위사업청 자료가 전국 집계만 가능하다는 설명은 국내조달에는 더 이상 적용되지 않는다. 국외조달·입찰참여는 전국 집계 유지. 근거, 주소 미분류 처리, 질병청 메타데이터 확인 한계는 `docs/AGENCY_METADATA_REVIEW.md` 참조. 기존 수치의 의미를 임의 변경하지 않는 요구사항 추적과 원본 대조 검증을 확장했다.

### 실제 변경한 공개 화면

자료 출처 영역에 ‘검사 결과를 어떻게 해석하나요?’ 펼침 안내를 추가했다.
검사 통과/보완 필요의 의미, 지역·기간·단위·항목 정의의 비교 조건,
품질 검사와 장기 신뢰성의 차이, 근거 중심 설명 순서를 제공한다.
기존 행별 오류 다운로드·자료 버전·배포 검증 기능을 이해하고 사용하는 안내이며
새 검사 엔진이나 예측 성능 향상으로 계산하지 않는다.

### 경험 설명 예시와 역할

- 목적: 서로 다른 기관 통계를 조회할 때 범위가 다른 자료를 같은 의미로 오해하는 문제를 줄이고자 했다.
- 작업: 지역 관할·자료 기간·단위·출처를 분리하고, 원본 대조·누락·중복 검사 및 보완 안내를 연결했다.
- 근거: 병역판정검사 105행·630개 수치·42개 전국 합계를 대조하는 코드와 오류 주입 테스트가 있다. 수치의 출처는 강의가 아니라 프로젝트 검증기다.
- 역할: 최희찬은 요구사항·자료 제공·문제 제기·결과 검토를 담당하고, Codex가 코드와 문서 작성을 지원했다.
- 한계: 사용자 오해 감소율·업무시간 절감·예측 성능 개선은 별도 측정하지 않았다.

### 방산 강의에서 적용하지 않은 영역

RF/레이다·항법·표적추적·제어, EMC/진동/충격/열 시험, 실제 장비 RAM 수치는
공개 통계 조회 화면의 구현 대상이 아니다. 요구사항 추적과 SW 검증 원칙을
선별 적용한 사실을 전체 방산 강의 기술의 구현 완료로 표현하지 않는다.

## 2026-09-24 방산 강의 원칙의 검사 근거 화면 연결

김도하 주요직무 강의 77쪽의 요구사항 추적·결함 관리와 2강 14쪽의 시험 기준 대조를 공개 통계 SW에 추가 적용했다.

- 실제 기능: 원자료 대조 영역에서 CHECK-01~07의 요구사항·합격 기준·결과·후속 조치를 표시한다. 대상은 병역판정검사 보관 자료다.
- 검사 항목: 파일 식별, 값 전수 대조, 중복, 인원 형식, 관할 누락, 전국 합계, 다운로드 일치.
- 근거 연결: 현 배포 보고서의 상태·스키마·필수 검사 목록·시각·원본 해시·행 수와 집계 수량을 확인한 경우에만 통과로 표시하고 JSON 보고서 다운로드를 제공한다.
- 보고서 부재·불일치: 모든 항목을 미확인으로 표시하고 항목별 확인 조치를 제시한다. 보고서 확인 실패는 원자료 자체의 오류가 입증됐다는 뜻이 아니다.
- 다시 확인은 보고서 재조회다. 브라우저에서 원본 대조 시험을 새로 수행하지 않는다. 실제 검사는 기존 빌드 검증기가 수행한다.
- CHECK 식별자는 기존 PUB 요구사항의 세부 검사 근거이며 공식 인증 번호가 아니다. 7개 검사 결과를 종합 위험 점수나 예측 정확도로 바꾸지 않는다.
- 검증: 보고서 누락, 검사 목록 누락, 원본 불일치, 잘못된 수량/형식/시각/스키마를 주입하는 Node 테스트를 CI에 연결했다.
- 구현: `public-statistics/validation-trace.js`, `app.js`, `tests/test_validation_trace.cjs`.

전자기·진동·충격·열 환경시험이나 레이다·제어·항법 기술을 구현했다는 주장은 포함하지 않는다.

## 2026-09-24 결함 처리와 재시험 기록

방산 주요직무 강의 77쪽의 결함 관리, 2강 14쪽의 기준 대조·원인 분석 원칙을 공개 통계 검토 기록에 적용했다.

- `문제 확인·수정·재시험 기록`에서 검사 ID, 기대 결과, 관찰 결과와 등록 시 지역/병역판정검사 연도/배포 버전을 기록한다.
- 확인 필요 → 수정 기록 → 재시험 통과 순서를 지킨다. 수정 기록 없이 바로 통과 처리하거나 근거 없이 다음 단계로 이동할 수 없다. 재시험 실패·재등록도 이력에 남는다.
- 기록은 사용자가 입력한 내용이며 자동 시험 결과와 구분한다. 상태 변경으로 원본이나 코드가 수정되는 것은 아니다.
- 브라우저 메모리에서만 보관하고 전체 이력을 JSON으로 내보낸다. 새로고침/창 닫기 후 보존, 가져오기, 서버 협업 기능은 구현하지 않았다.
- 등록 시 선택값을 복사해 보존하며 이후 지도 선택이 과거 기록을 바꾸지 않는다.
- 상태 전이·근거 필수·자료 버전·이력 보존·입력 제한을 단위 테스트로 확인한다.
