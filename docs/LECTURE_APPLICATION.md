# 강의자료 적용 기록 — 공개 통계 화면의 데이터 품질과 검증

## 검토 범위와 해석

사용자가 제공한 김도하 강의자료 4종을 검토했다. 첫 두 PDF는 텍스트 추출이 대부분 불가능해 목차·관련 페이지를 이미지로 확인했다. 전 페이지 정독·OCR 완료를 주장하지 않는다. 아래 쪽수는 PDF의 1부터 시작하는 실제 페이지 번호다. 강의 원문 PDF·이미지는 저장소에 재배포하지 않는다.

강의에서 확인한 원칙과 이를 소프트웨어에 옮긴 설계 판단은 구분한다. 아래 자동 검증 구현은 프로젝트에 맞춘 자체 적용이며 강사가 제시한 트리가드 설계가 아니다.

| 자료 | 확인한 페이지와 내용 | 적용 또는 보류 |
|---|---|---|
| `0820_2026_숭실대_방산직무특강_김도하(a) (1).pdf` | 3–4쪽 분류·핵심기술 목차, 48쪽 전기전자·기계항공·CS/SW 협업 구분 | **설명 범위에 적용:** 공개 통계 SW 경험과 하드웨어·체계개발 경험을 구분. 구체적인 무기 설계·탐지·교전 내용은 공개 통계 기능에 적용하지 않음 |

## 요구사항–검증 연결표

| ID | 요구사항 | 구현 | 합격 기준 및 확인 |
|---|---|---|---|
| PUB-01 | 원본과 표시 수치의 일치 | `scripts/validate_public_statistics.py` | 원본 SHA-256 일치 및 연도·지방청 키별 6개 수치 전부 일치 |
| PUB-02 | 중복·누락·잘못된 인원 수 차단 | 동일 검증기 | 연도/지방청 키 유일, 원자료 행 집합과 동일, 음수·소수·불리언·NaN·null 거부 |
| PUB-03 | 합계와 다운로드 일치 | 동일 검증기 | 연도마다 14개 지방청 및 전체 행 존재, 6개 전국 합계 일치, 다운로드 CSV의 행과 수치 일치 |
| PUB-04 | 검증 실패 시 배포 산출 중단 | `scripts/build_public_statistics.py` | 검증을 먼저 실행하고 실패 시 새 `dist` 작성 없이 비정상 종료. 기존 운영 배포에는 새 산출물을 적용하지 않음 |
| PUB-05 | 검증 근거와 한계를 사용자에게 표시 | `public-statistics/app.js`, `index.html` | 이번 빌드에서 생성한 보고서에 한해 원본 해시·행 수 일치 확인 후 범위/검사시각 표시. 보고서 오류는 검증 미확인으로 표시 |
| PUB-06 | 변경마다 재현 가능한 검사 | `.github/workflows/public-statistics.yml` | 오류 주입 테스트와 빌드 검사 실행, 결과 JSON을 CI 아티팩트에 보관 |
| PUB-07 | 통합 관할·연도 변경 유지 | 기존 `selectRegion`, `renderDataGuide` | 대구/경북 동시 강조, 지방청 전체 수치 한 번 표시, 연도 변경 시 안내 갱신. 기존 실사이트 검증 기록은 PR #28·#29 |

## 공개 통계 서비스의 실패 모드와 조치

| 실패 모드 | 사용자 영향 | 탐지/처리 | 남은 한계 |
|---|---|---|---|
| 원본 갱신 후 표시 스냅샷 미갱신 | 오래된 수치를 새 자료로 오해 | 해시 및 원본값 대조 실패로 빌드 중단 | 새 원본의 공식성·정확성은 사람이 확인 |
| 같은 연도·지방청 중복 | 중복 표시/집계 | 키 중복 검사 실패 | 기관의 관할 정의 변경은 수동 검토 |
| 값 누락 또는 잘못된 숫자 | 0명으로 오해 | 배포 차단, 화면에서는 유효하지 않은 값에 자료 없음 | 원본 자체의 누락 원인은 추가 확인 |
| 배포 보고서 로딩 실패 | 검증 완료로 잘못 인식 | 검증 미확인 문구, 통계 조회는 유지 | 네트워크 장애의 상시 모니터링은 미구현 |
| 공식 기준일·허가 조건 미확인 | 최신성·재사용 범위 오해 | 파일명 기준일과 미확인 범위 명시 | 개별 공식 데이터셋 링크/이용조건 확인 필요 |

위 표는 공개 통계 SW의 정성적 실패 모드 기록이다. 정식 FMEA 인증, 수치 RPN 평가 또는 군사 장비 신뢰성 분석을 수행했다는 뜻이 아니다.

## 실제 검증 결과와 주장 범위

- 현재 보관 원자료: 7개 연도(2019–2025), 14개 지방청과 전국 합계, 총 105행.
- 직접 대조한 숫자: 630개. 연도별 전국 합계 검사: 42건. CSV 다운로드: 7개.
- 오류 주입을 포함한 단위 테스트 7개 통과(잘못된 숫자 테스트 안에 5종 입력 하위 사례).
- 이 결과는 원자료와의 데이터 정합성이다. 예측 정확도 100%, 공식 통계 검증, 기관 도입 성과, 인증 또는 실시간 서비스 가용률이 아니다.
- 배포 결과 보고서는 빌드마다 `dist/data/validation_report.json`으로 새로 생성한다. 성공 여부를 소스 코드에 고정하지 않는다.

## 역할을 분리한 면접 설명

**문제:** 같은 지방청이 여러 시·도를 담당하는 통계를 개별 지역의 값처럼 오해할 수 있고, 코드가 저장소에 반영돼도 운영 배포와 다를 수 있었다.

**최희찬의 역할:** 서비스 요구사항을 제시하고, 기존 지도/통합 관할 동작의 차이를 지적했으며, 원자료 확인 안내와 강의 원칙 적용을 요청했다. 최종 결과 검토와 프로젝트 운영을 담당한다.

**AI 지원 구현:** Codex가 UI·검증기·CI·오류 사례 테스트를 작성하고 배포 및 브라우저 확인을 수행했다. 최희찬이 모든 코드를 직접 작성했다고 표현하지 않는다.

**결과:** 공개 통계 화면의 지역/연도 조회와 출처 안내를 구현했고, 105행·630개 수치 및 42개 합계 검사를 배포 절차에 연결했다. 현재 결과는 데이터 정합성 개선이며 실제 행정 업무 시간 절감이나 운영 효과는 측정하지 않았다.

**질문 대응:**
- “강의의 기술을 그대로 구현했나?” → 일반적인 요구사항 추적·기준 기반 검증·역할 중심 설명 원칙을 적용했다. 레이다/EMC/진동/열설계 시험을 수행한 것은 아니다.
- “반도체·스마트제조와 어떻게 이어지나?” → 원자료 추적, 데이터 계약, 결함 재현, 변경 검증이라는 SW 품질 관리 경험을 설명할 수 있다. 실제 팹 공정 제어·수율 개선 경험과는 구분한다.
- “향후 측정할 성과는?” → 사용자 조회 성공률과 출처 이해도 등을 별도 실험으로 평가할 수 있지만, 현재 달성치로 쓰지 않는다.
