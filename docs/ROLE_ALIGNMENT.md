# TriGuard AI 직무 연계와 인터뷰 가이드

이 문서는 TriGuard AI의 구현 증거를 공공데이터 분석, 위험관리, 데이터 기반 행정 및 의사결정 지원 직무의 언어로 설명하기 위한 포트폴리오 보조자료다. 채용·교육 자료는 설명 구조의 참고자료이며 정책효과나 미래예측 성능의 기술적 증거가 아니다.

## 한 문장 정의

TriGuard AI는 5개 공공기관의 12종 데이터를 전국 14개 지방청 단위로 전처리하고, 인력·감염병·물자 위험을 통합해 우선점검 지역과 대응 정보를 제공하는 Streamlit 기반 의사결정 지원 프로토타입이다.

## 직무 키워드에서 검증 증거까지

| 직무 키워드 | 프로젝트에서 수행한 행동 | 확인 가능한 증거 | 주장하지 않을 내용 |
|---|---|---|---|
| 다기관 데이터 통합 | 서로 다른 스키마의 12종 공개데이터를 자동 감지·파싱·지역 단위로 정규화 | `data/`, `modules/preprocess.py`, 앱 데이터 로더 | 기관 간 실시간 데이터 플랫폼 연동 |
| 위험지표 설계 | 인력·감염병·물자 구성요소와 가중치를 분리해 14개 지방청 통합점수 산출 | `modules/risk_engine.py`, 가중치 검증 | 가중치가 정책적으로 최적이거나 인과적으로 확정됐다는 주장 |
| 우선순위 지원 | 동일 위험등급 안에서도 점수 기준 상위 지역을 우선점검 대상으로 표시 | `app.py`, 대시보드 결과표·지도 | 실제 기관이 경보·배치 결정을 수행했다는 주장 |
| 정합성 검증 | Rule-based 등급을 RandomForest가 얼마나 재현하는지 5-fold CV로 확인 | `modules/ml_engine.py`, README의 정합성 설명 | 93%를 미래 위험예측 정확도로 표현 |
| 이상·연관 분석 | Z-score 이상지역과 인력–감염병 상관관계를 보조지표로 제공 | ML·시각화 모듈 | 상관관계를 감염병의 병력감소 원인으로 해석 |
| 사용자 인터페이스 | 실제 데이터·시뮬레이션 모드, 지도·상세지표·가이드·CSV 다운로드 구현 | `app.py`, `modules/visualize.py` | 운영기관 배포·보안·접근통제 완료 |
| 데이터 책임성 | 출처·스냅샷·최신성·재배포 조건과 지역단위가 없는 물자지표 한계를 공개 | README·데이터 출처 고지 | 최신 실시간 현황 또는 전국 정책효과 검증 |

## 직무별 연결

### 공공데이터·데이터 분석

여러 기관의 상이한 CSV 구조를 공통 분석단위로 맞추고, 데이터가 없는 경우와 오류를 사용자에게 표시하는 경험을 강조한다. 데이터 스냅샷이 최신 현황을 보장하지 않는다는 점을 함께 말한다.

### 위험관리·의사결정 지원

복수 위험요인을 하나의 점수로 통합하면서 구성요소·가중치·경고를 분리하고 우선점검 순서를 제시한 경험을 강조한다. 점수는 확정적 정책판정이나 미래예측이 아니라 비교 가능한 위험 신호다.

### 데이터 기반 행정·서비스 기획

행정 현장의 문제의식을 데이터 흐름, 지도, 상세지표와 대응 가이드로 전환한 경험을 강조한다. 실제 기관 사용자 조사, 업무시스템 연동, 운영성과 측정은 후속 검증 범위다.

## 자소서 경험 구성

1. **상황:** 병력운용 위험은 인력·감염병·물자 정보가 기관별로 분리돼 있어 지역별 우선순위를 한 화면에서 보기 어렵다.
2. **문제:** 데이터의 단위와 지역 구분이 다르고, 하나의 점수가 실제 미래예측처럼 오해될 위험이 있다.
3. **행동:** 12종 데이터를 파싱·정규화하고 14개 지방청 기준으로 통합했으며, 구성요소별 점수·가중치 검증·경고·지도·상세정보·CSV 출력을 구현했다.
4. **결과:** 14개 지방청의 위험등급과 동일 등급 내 우선점검 순서를 제공하는 Streamlit 프로토타입을 구축했다. RandomForest 결과는 Rule-based 등급과의 정합성 점검으로 제한해 표시했다.
5. **한계:** 물자 Risk는 지역 구분이 없어 전국 공통값이며, 가중치의 정책적 타당성·미래예측·실제 대응성과는 검증하지 않았다.
6. **향후계획:** 최신 데이터 자동수집, 기관별 지표 정의 검토, 시계열 외부검증, 사용자 테스트와 대응 전후 KPI를 분리해 검증한다.

## 예상 꼬리질문

### 93%는 무엇을 의미하나?

Rule-based Risk Score가 만든 등급과 RandomForest 분류 결과 사이의 교차검증 정합성이다. 미래 감염병이나 병력 부족을 93% 정확도로 예측했다는 뜻이 아니다.

### 왜 가중합을 사용했나?

구성요소와 가중치가 사용자에게 보이고 조정 가능하며, 초기 의사결정 지원 프로토타입에서 설명하기 쉽기 때문이다. 현재 가중치가 유일한 최적값이라는 근거는 없다.

### 물자 Risk를 왜 전국 공통값으로 적용했나?

사용한 방위사업청 자료에 지방청 단위 구분이 없기 때문이다. 임의 지역배분 대신 외생 공통위험으로 적용하고 그 한계를 화면과 README에 공개했다.

### 상관관계가 원인을 의미하나?

아니다. Pearson 상관계수는 함께 움직이는 정도를 보여줄 뿐이며 인과관계나 정책효과를 증명하지 않는다.

### 본인의 역할과 AI 에이전트의 역할은 무엇인가?

프로젝트 책임자는 공공행정 문제 정의, 서비스 기획, 데이터·모듈 통합과 최종 검토를 담당했다. 팀원과 AI 에이전트의 조사·개발·감사 작업은 Git 기록과 PR 설명에 분리해 남긴다.

## 참고 범위

자소서·이력 점검 자료에서는 직무 키워드를 행동과 증거로 연결하고, 상황·문제·행동·결과·한계·향후계획으로 경험을 구성하는 원칙만 참고했다. 강의 예문·표·양식은 복제하지 않으며 기술 성능의 근거로 사용하지 않는다.
